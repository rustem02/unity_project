Техническое задание.
Цель:
Разработать VR проект. Визуал: достаточно примитивов. Не использовать готовые ассеты (кроме Unity решений). Не использовать инструменты DI. Только написание архитектурных решений и механик. Для визуализации действий необходимо использование подсветки Highlight Plus\Outline.
Грамотное оформление UI, внимание к деталям, аккуратность кода и организации хранения скриптов\префабов\материалов обязательна. Способ перемещения в VR- скольжение или телепортация.
Описание:
Пользователь появляется в "Лобби". Есть меню перехода в сцену тренировки. Интеракция с UI при помощи клавиатуры\мыши + контроллеры. Пользователь нажимает кнопку и переходит на сцену тренировки.
В сцене тренировки есть сценарий выполнения\прохождения, он состоит из 3 групп шагов (Группа шагов- блок связанных по смыслу шагов, на практике это может быть "проверка документов"\"поиск нарушений" и т.п.), в каждой группе 3 шага (Шаг- конкретный шаг сценария, где от пользователя ожидается какое-то действие. Оно так же может быть правильным или неправильным, соответственно шаг может закончиться успехом или нет).
Каждый шаг может содержать в себе 1 или несколько ожидаемых от пользователя действий (например: подойти в подсвеченную зону и нажать на кнопку).
Список возможных действий: дойти до точки интереса, взять объект(граб), кликнуть на объект (поинтер\луч), нажать на кнопку UI.
Список возможных нарушений: подошёл не к той точке, кликнул не на ожидаемый объект, нажал не на ожидаемую кнопку UI.
При наступлении нарушения- звуковой сигнал нарушения, отметка в шаге о выполнении с ошибкой.
При выполнении правильно- звуковой сигнал правильного выполнения, отметка в шаге о надлежащем выполнении.
При окончании шагов в группе шагов -> переход к следующей группе шагов.
Также может быть нарушение порядка выполнения. В группе шагов есть 3 шага, они имеют линейную последовательность. Например, выполнение шага 2 перед шагом 1- это нарушение последовательности. При нарушении последовательности, закрываем выполнение всей группы
шагов и переходим к следующей. На оконченных шагах ставится статус(выполнен с ошибкой\без) на неоконченных ставим (пропущенный).
По окончанию сценария, подводим итог: выводим UI с результатами. Перечень шагов и их статус.
Есть кнопки "Попытаться ещё" (Restart) + “Возврат в Лобби”.
Как сообщать пользователю о доступных шагах, текущей группы шагов:
Вывод информационного сообщения о порядке ожидаемых действий при активации группы шагов. Подсветка\голосовая подсказка\звуки для уведомления пользователя о доступных шагах приветствуются, но не обязательны.
Общие требования, при выполнении задания:
• Код должен быть читабельным, покрыт комментариями и легко расширяемым.
• Код должен быть прост, лаконичен и понятен.
• UI должен быть хорошо читаем в VR.
• Зависимость на события (не использовать готовые решения).
• Соблюдение принципов SOLID и КОП.
• Интерфейсом(UI) можно управлять как контроллерами, так и мышью.
• Рендер URP.
• Внимание к деталям, аккуратность, вовлечённость и инициатива.
Пример структуры шага (образец для примера, использовать необязательно):
{
 "Group": "Проверка документов",
 "Steps":
[
 {"id": 1, "description": "...", "expectedAction": "подойти", "target": "зона1"},
 {"id": 2, "description": "...", "expectedAction": "граб", "target": "паспорт"},
 {"id": 3, "description": "...", "expectedAction": "нажать кнопку", "target": "Подтвердить"}
 ]
}
